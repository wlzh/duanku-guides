## 一、DNSHE 是什么？

DNSHE 是一个提供免费域名注册与 DNS 服务的平台。官网介绍其定位是为开发者、学生和开源爱好者提供简单、快速、免费的域名服务。

![DNSHE官网截图](https://869hr.uk/2026/tech/2026freedomaincard-10-cloudflare/images/DNSHE%E5%85%8D%E8%B4%B9%E5%9F%9F%E5%90%8D%E6%B3%A8%E5%86%8C%E6%95%99%E7%A8%8B-%E5%AE%9E%E6%B5%8Bccwu.cc%E5%88%9D%E5%A7%8B10%E5%B9%B4%E6%9C%89%E6%95%88%E6%9C%9F%E6%97%A0%E9%99%90%E7%BB%AD%E6%9C%9F%E6%B0%B8%E4%B9%85%E4%BD%BF%E7%94%A8-%E5%8F%AF%E6%89%98%E7%AE%A1Cloudflare%E7%94%A8%E4%BA%8EVPS-%E9%9D%A2%E6%9D%BF%E4%B8%8E%E8%87%AA%E5%BB%BA%E5%8D%9A%E5%AE%A2-3a89f54f860b7329e1e331847f528242.png)

从实际使用来看，DNSHE 更适合用作"免费二级域名/子域名注册服务"。它并不等同于自己单独注册一个完全独立的 `.com` 顶级域名，但对于测试、学习和临时项目已经足够使用。

目前可注册的后缀包括（后期可能会有变化)：

`ccwu.cc`
`bbroott.com`
`cc.cd`
`cn.mt`

不同后缀的有效期、Cloudflare 兼容性、续期规则和平台策略可能会有所不同。网络上也有用户反馈，DNSHE 部分后缀支持托管到 Cloudflare，但不同后缀的兼容情况可能存在差异。

所以在实际选择时，建议优先注册自己测试通过、后台状态清晰、有效期更长的后缀。

## 二、这次实测的四个免费域名后缀有什么区别？

我这次一共注册了四个域名：

| 域名 | 初始有效期 | 状态特点 | 推荐用途 |
| -- | -- | -- | -- |
| `kjlw.ccwu.cc` | 约 10 年 | 已解析，长期有效期 | 长期备用、Cloudflare 测试、VPS 入口 |
| `kjlw.bbroott.com` | 约 1 年 | 未解析 | 补充测试、临时项目 |
| `kjlw.cc.cd` | 约 1 年 | 未解析 | 临时解析、备用域名 |
| `kjlw.cn.mt` | 约 1 年 | 未解析 | 测试用途、短期项目 |

从后台显示来看，`ccwu.cc` 是目前最值得优先选择的后缀，因为它注册后直接给到 10 年有效期。

这个特点很重要。

很多免费域名虽然也能注册，但每年都要手动续期。一旦忘记续期，域名可能失效，例如我们先前也是给小伙伴分享注册的 [**us.kg免费域名注册**](https://kejilaowang.com/register-us-kg-free-domain-and-use-with-cloudflare/)都是一年有效期然后无限续期，就有点麻烦需要设置提醒，相同的如果我们使用过程中忘记去设置续期，这样后期绑定的 VPS、面板、博客、Cloudflare 配置都会受到影响，带来不不必要的麻烦。

而DNSHE提供的 `ccwu.cc` 初始就是 10 年有效期，至少在当前规则下如果稳定可靠那么就非常的有价值，可以减少了频繁续期带来的不确定性。

不过这里也要说明：**免费域名的长期可用性最终取决于平台规则，不能完全等同于自己付费持有的独立域名。**因此它适合作为测试域名、备用域名、学习环境域名，不建议直接用于公司官网、长期品牌站或核心商业项目，这里只是网络收集知识分享，并不做永久使用的承诺。

## 五、如何把 DNSHE 免费域名托管到 Cloudflare？

DNSHE 域名注册完成后，如果你想更方便地使用 Cloudflare 的 CDN、SSL/TLS、防护、缓存、规则、Zero Trust 等功能，就可以把 DNS 服务器托管到 Cloudflare。

Cloudflare 官方文档说明，完整接入一个域名时，需要将域名的 nameserver 修改为 Cloudflare 分配的名称服务器，然后由 Cloudflare 管理该域名的 DNS 解析。

整体流程如下：

1. 注册 DNSHE 免费域名
2. 登录 Cloudflare 添加站点
3. Cloudflare 分配两个 nameserver
4. 回到 DNSHE 修改 DNS 服务器
5. 等待 Cloudflare 检测生效
6. 在 Cloudflare 添加解析记录

### 1. 在 Cloudflare 添加站点

登录 Cloudflare 后，点击"添加网站"。

![Cloudflare添加站点截图](https://869hr.uk/2026/tech/2026freedomaincard-10-cloudflare/images/DNSHE%E5%85%8D%E8%B4%B9%E5%9F%9F%E5%90%8D%E6%B3%A8%E5%86%8C%E6%95%99%E7%A8%8B-%E5%AE%9E%E6%B5%8Bccwu.cc%E5%88%9D%E5%A7%8B10%E5%B9%B4%E6%9C%89%E6%95%88%E6%9C%9F%E6%97%A0%E9%99%90%E7%BB%AD%E6%9C%9F%E6%B0%B8%E4%B9%85%E4%BD%BF%E7%94%A8-%E5%8F%AF%E6%89%98%E7%AE%A1Cloudflare%E7%94%A8%E4%BA%8EVPS-%E9%9D%A2%E6%9D%BF%E4%B8%8E%E8%87%AA%E5%BB%BA%E5%8D%9A%E5%AE%A2-97257fa1ef0c295989523d4e65b6864e.png)

输入你注册的免费域名，例如：`kjlw.ccwu.cc`

Cloudflare 会开始扫描域名，并给你分配两个 DNS 服务器地址。

![Cloudflare分配NS截图](https://869hr.uk/2026/tech/2026freedomaincard-10-cloudflare/images/DNSHE%E5%85%8D%E8%B4%B9%E5%9F%9F%E5%90%8D%E6%B3%A8%E5%86%8C%E6%95%99%E7%A8%8B-%E5%AE%9E%E6%B5%8Bccwu.cc%E5%88%9D%E5%A7%8B10%E5%B9%B4%E6%9C%89%E6%95%88%E6%9C%9F%E6%97%A0%E9%99%90%E7%BB%AD%E6%9C%9F%E6%B0%B8%E4%B9%85%E4%BD%BF%E7%94%A8-%E5%8F%AF%E6%89%98%E7%AE%A1Cloudflare%E7%94%A8%E4%BA%8EVPS-%E9%9D%A2%E6%9D%BF%E4%B8%8E%E8%87%AA%E5%BB%BA%E5%8D%9A%E5%AE%A2-2f7be5f3ebaffa62c94ab00a8ab94378.png)

一般格式类似：

`xxx.ns.cloudflare.com`

然后把你后台生成的这两个就是后面要填写到 DNSHE 后台的 nameserver。

### 2. 回到 DNSHE 修改 DNS 服务器

在 DNSHE 后台找到对应域名，点击"DNS 服务器"。

将默认 DNS 服务器改成 Cloudflare 提供的两个 nameserver。

常见记录如下：

## 六、Cloudflare 橙云和灰云怎么选？

Cloudflare 的 DNS 记录有两种常见状态：

**Proxied 橙云**：流量经过 Cloudflare。
**DNS only 灰云**：只做 DNS 解析，不要CDN那就不开启云朵不经过 Cloudflare。

Cloudflare 官方文档说明，开启代理状态后，HTTP/HTTPS Web 流量可以经过 Cloudflare 网络，并使用其缓存、安全和性能相关功能；DNS only 则只是返回 DNS 解析结果。

简单建议如下：

| 使用场景 | 建议状态 |
| -- | -- |
| WordPress 博客 | 橙云 |
| 静态网站 | 橙云 |
| 工具导航页 | 橙云 |
| 普通 Web 项目 | 橙云 |
| SSH 连接 | 灰云 |
| VPS 面板后台 | 谨慎使用，建议灰云或访问控制 |
| S-UI / 3X-UI 后台 | 不建议裸奔公网 |
| NAS 远程访问 | 建议配合 HTTPS、访问控制或 Cloudflare Tunnel |

对于新手来说，橙云不是万能的。它主要适合 HTTP/HTTPS 网站流量。

如果你把所有服务都强行走橙云，可能会出现端口不支持、协议不兼容、证书异常、连接失败等问题。小伙伴要注意排查，我们博客里也有很多有关Cloudflare有关的设置包括CDN相关的知识感兴趣也可以一起学习探讨一下。
